# FoodProof — Staged agent assignments

Use these after the team's document review. Assign one ticket per agent; no giant “build everything” prompt. All agents read the root `AGENTS.md` and the handoff index. The integration owner freezes shared paths before parallel work.

## First assignment — T0

Read `../README.md`, FOODPROOF_BUILD_HANDOFF.md, FOODPROOF_PRD.md, DESIGN.md, the technical specification and API supplement. Implement T0 only in this repository. Inspect current contents first. Scaffold the agreed Next.js/TypeScript application around the existing documentation. Select compatible current versions using official documentation, add one lockfile, shared Zod contracts, migrations, environment validation, service interfaces and design tokens. Preserve documentation and design assets. Build the public-home skeleton matching Clear Signal. Run and report actual typecheck/build checks. Record shared paths and contract decisions before assigning other agents. Do not implement the entire app or claim unconfigured services work.

## T1 — persistence and access

Implement T1 only on the assigned service paths against T0 schemas. Complete a private report save/reopen slice with real demo Supabase, invitation sessions and ownership checks before expanding to evidence and publication transactions. Follow the technical/API contracts. Ask the integration owner for schema changes. Verify two-user isolation, reviewer restrictions, stale versions and withdrawal. Report exactly which integrations were tested.

## T2 — reporter UI

Implement T2 only using the shared service client and approved Clear Signal design. Read screen sections 5–9 and the prototype-to-build mapping. Complete incomplete-save/reopen, evidence roles, confirmed facts, sharing preview, editable action draft and separate external histories in successive working slices. Fixtures must be labelled and isolated. Do not edit global contracts or invent successful sends/persistence. Coordinate API integration with T1.

## T3 — community and review UI

Implement T3 only on assigned homepage/entry/feed/detail/reviewer/shell paths. Match Clear Signal while implementing all functional screen states. Public home must never query pilot reports. Invitation determines role; no public reviewer toggle. Show exact submitted snapshot with explicit review reasons and stale-conflict handling. Integrate approved projections and private correction flags through shared services.

## T4 and T5 — integration and release evidence

Integrate completed slices incrementally. Run FOODPROOF_ACCEPTANCE_CHECKLIST.md against actual services, verify configured AI on readable/unreadable examples, and inspect real Mixpanel ingestion with consent accepted/declined. Resolve differences centrally. Update README with verified commands and setup. Report failures and blockers accurately. Deployment and invited distribution follow the user-authorized destination and owner process; public launch is outside this assignment.

## Independent team review

Review the diff against PRD requirements and acceptance checks. Prioritize exposure, data loss, snapshot correctness, false statuses, scope drift and inaccessible core actions. Record actionable findings with trigger, expected/actual behaviour and affected requirement. Do not approve merely because screenshots look polished or builds pass.
